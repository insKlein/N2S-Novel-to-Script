# 分工说明 — 郑闵侨

> 本项目为 **AI 小说转剧本工具（N2S: Novel-to-Script）**，目标是将 3 章节以上中文网络小说自动转换为结构化剧本（YAML 格式）。

## 个人分工：前期调研 + 框架搭建 + 设计总结

我的工作集中在项目孵化最前期的三个关键阶段，为后续开发建立清晰的设计蓝图和技术边界。

---

## 阶段一：前期灵感数据搜寻

### 参考项目调研

- 收集并研究了 MIT 开源参考项目 `novel-to-script-team`（Supreme-Ultimate/novel-to-script-team）
- 该参考项目是一个完整的多 Agent 协作网文改编全流程生产系统，覆盖"小说→剧本→分镜→视频"全链路
- 对其完整架构做了逐一拆解分析：
  - **17 个 Agent**：理解每个专业角色的职责、输入输出和协作关系
  - **27 个 Skill**：梳理每条执行规则的定义步骤和产出格式
  - **23 个 Reference**：筛选方法论和标准中可复用的部分
  - **10 个 Script**：评估自动化工具脚本的复用价值

### 比赛要求分析

- 研读比赛评审标准（完整度 40% + 开发过程 40% + 演示表达 20%）
- 结合 3 天时间限制，确定"聚焦剧本创作核心、删除非必要链路"的策略

## 阶段二：框架建造

### 2.1 核心设计决策：可拍性 vs 分镜的三层边界模型

这是整个项目**最重要的设计决策**，决定了哪些内容属于"剧本创作"应当保留，哪些属于"导演/分镜师工作"应当删除：

```
┌──────────────────────────────────────────────┐
│  第三层：导演分镜（删除）                       │
│  镜号序列、运镜方案、九宫格节奏板、转场手法      │
│  → 属于导演/分镜师，不属于编剧                  │
├──────────────────────────────────────────────┤
│  第二层：编剧镜头意识（保留 — 轻量可选）         │
│  景别提示（特写/中景/全景）、关键动作强调        │
│  → 编剧用文字告诉读者"这一刻很重要，应放大"      │
├──────────────────────────────────────────────┤
│  第一层：可拍性基本功（保留 — 强制）             │
│  用动作/表情/道具替代心理描写、Show Don't Tell   │
│  → 剧本区别于小说的本质特征                      │
└──────────────────────────────────────────────┘
```

判断标准：**"这个信息是写给演员/摄影看的，还是写给剪辑/后期看的？"**

- 写给演员 → 剧本内容
- 写给摄影（基础景别）→ 剧本可选提示
- 写给剪辑/特效 → 不属于剧本

### 2.2 筛选决策

从参考项目中筛选出对"小说→剧本"有价值的内容，每一项都有明确的保留/删除理由：

| 类别 | 原始数量 | 保留 | 删除 | 保留率 |
|------|---------|------|------|--------|
| Agent | 17 | 10 | 7 | 59% |
| Skill | 27 | 12 | 15 | 44% |
| Reference | 23 | 13 | 10 | 57% |
| Script | 10 | 5 | 5 | 50% |
| 流水线阶段 | 6 | 4+1 | 2 | — |

**保留的 10 个 Agent**：
`knowledge-curator` / `novel-analyzer` / `insight-architect` / `episode-architect` / `emotion-architect` / `script-writer` / `visual-storyteller` / `review-director` / `script-comparator` / `continuity-recorder`

**删除的 7 个 Agent**（视频/分镜/图片相关）：
~~storyboard-director / storyboard-artist / storyboard-coach / art-designer / animator / image-generator / image-to-prompt~~

### 2.3 四层架构设计

```
用户命令 (~analyze, ~write N 等)
  → Agent 层 (10 个专业角色，阶段负责人)
    → Skill 层 (12 个执行规则，定义步骤和产出格式)
      → Reference 层 (13 个方法论和标准)
        → Script 层 (5 个自动化工具脚本)
          → outputs/{剧本名}/ (阶段产物、审核记录、状态文件)
```

### 2.4 4+1 阶段核心流水线

每阶段执行 **生成→审核→回改→复审→PASS** 循环，每个关键阶段双重审核（业务审核 + 合规审核）。

| 阶段 | 命令 | 工作流 | 产出 |
|------|------|--------|------|
| 阶段1 | `~analyze` | novel-analyzer → insight-architect → review-director | 清洗文本、分析报告、角色档案、洞察报告 |
| 阶段2 | `~plan` | episode-architect → emotion-architect → review-director | 分集目录、项目进度、情绪曲线 |
| 阶段3 | `~write N` | script-writer → visual-storyteller → review-director → continuity-recorder | 第 N 集剧本 (YAML)、风格分析、视觉叙事报告 |
| 阶段4 | `~review N` | script-comparator → review-director | 逐一对比分析、综合审核报告 |
| 阶段6 | `~final-check` | 自动化检查 | UTF-8 检查、称呼一致性、文件完整性 |

### 2.5 YAML 结构化剧本 Schema 设计

设计了完整的 YAML 输出格式，替代参考项目的 Markdown 输出。核心结构：

```yaml
meta: { script_title, source_novel, total_episodes, ... }
adaptation_summary: { genre, sub_genre, core_conflict, main_characters, ... }
episodes:
  - episode_number: 1
    episode_meta: { duration, scene_count, emotion_peak, hook_type }
    scenes:
      - scene_id: 1
        location: { time, place, environment, lighting }
        emotion: "绝望→震惊"
        elements:
          - { type: "action" | "dialogue" | "inner_voice" | "flashback" | "screen_text" | "sound_effect", ... }
        conflict: { type, intensity: 1-5, description }
    ending_hook: { type, content, intensity: 1-5 }
quality_metrics: { avg_sentence_length, dialogue_ratio, ... }
```

`camera_note` 取值严格限制为 `特写 | 近景 | 中景 | 全景 | 远景`，不含运镜术语。

### 2.6 量化质量标准

制定了 9 项可量化指标，用于评估生成剧本质量：

| 指标 | 目标值 |
|------|--------|
| 句子长度 | 10-14 字符 |
| 对话比例 | 70-80% |
| 视觉标记密度 | 3-5 个/100 字 |
| 网文感关键词密度 | 1.5-2.5 个/100 字 |
| 情绪形容词密度 | ≤2 个/千字 |
| 动作描写占比 | ≥30% |
| 每集场景数 | 2-3 个 |
| 每集冲突数 | ≥2 个 |
| 3 秒入冲突 | 强制 |
